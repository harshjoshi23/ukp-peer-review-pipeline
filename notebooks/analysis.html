Peer Review Data Wrangling¶

An executable walkthrough in seven stages¶

This notebook explains and verifies the pipeline implemented in solution.py. Run the cells from top to bottom. Saved tables and charts show the supplied dataset. Changing INPUT_CSV in Stage 1 reruns the analysis on a different file.

The programming submission consists of solution.py and results.json. This notebook and its HTML copy are companions for understanding and inspection. The script runs independently with Python's standard library. The notebook additionally uses pandas, NumPy, Matplotlib, and the Jupyter display environment.

  1. Understand the task and define the data contract
  2. Parse the CSV and inspect the raw data
  3. Validate, discard malformed records, and convert types
  4. Explore valid records and compute statistics
  5. Derive the fields needed for rule evaluation
  6. Evaluate and explain all seven anomaly rules
  7. Verify generalization and reproduce the final output

Sources: original assignment PDF, provided data folder, and the earlier due-date notebook as a reference for the narrated analysis structure. The required behavior comes from the UKP task.

1. Understand the task and define the data contract¶

One row represents a review. Several valid reviews can belong to the same paper or reviewer. The output must describe all valid rows, including duplicates and rows that trigger anomalies. Malformed rows are discarded before computing means, modes, correlations, or anomaly flags.

There is no prediction target or model fitting. Generalization means applying the same rules to newly generated records, without depending on particular IDs, row numbers, or sample totals.

The paths below locate the supplied folder structure. To analyze another dataset, change only INPUT_CSV. The notebook imports the actual submission script so the walkthrough cannot silently drift into a separate production implementation.

Decisions about preprocessing¶

Operation Treatment in this task Reason
Missing required values Discard the malformed row Imputation would add observations the specification excludes.
Missing free text Preserve it Empty titles or review text are not listed as reasons for rejection.
Numeric conversion Parse exact integer/float types and enforce bounds A decimal string such as 3.0 does not parse as an integer.
Date conversion Parse ISO-8601 and compare UTC instants Free-form date guessing could accept malformed strings.
Scaling or normalization Keep the original scales Anomaly thresholds refer to the original 1–5 and 1–10 scales.
Categorical encoding Preserve named categories Exact labels are part of the required output schema.
Duplicates Retain and flag every valid occurrence after the first Duplicates still contribute to statistics and consensus.
Statistical outliers Retain and flag A valid score of 10 can be an outlier; an invalid score of 11 is discarded.
Feature derivation Calculate rule inputs and diagnostic time intervals These derived columns explain decisions without changing source values.
Train/test split Exercise separate generated inputs in verification There is no learned model to train or tune.

2. Parse the CSV and inspect the raw data¶

Use a CSV parser with newline=''. Splitting on commas or iterating over physical lines as if each were a record would corrupt quoted text and multiline records.

Capture reader.line_num + 1 before reading a record. After reading, line_num identifies its last physical line. The audit below preserves both positions and the number of parsed fields. No numeric or date inference occurs during ingestion.

3. Validate, discard malformed records, and convert types¶

The diagnostic function records all detected validation failures for each raw record. One malformed row can have several failures, so the reason counts need not sum to the number of discarded rows. Its accept/reject decisions are checked against parse_review in the submission script.

Datetime parsing uses datetime.fromisoformat, with terminal Z normalized to +00:00 for Python 3.9 compatibility. Explicit offsets are converted to UTC. Unzoned values use the input's stated UTC timezone. This is an explicit interpretation of the input contract.

def validation_issues(values):
    if len(values) != len(solution.COLUMNS):
        return ["field_count"]
    data = dict(zip(solution.COLUMNS, values))
    issues = []
    for field in ["submission_id", "reviewer_id"]:
        if not data[field].strip():
            issues.append(f"{field}: empty")
    for field, allowed in [("track", solution.TRACKS),
                           ("recommendation", solution.RECOMMENDATION_BANDS)]:
        if data[field] not in allowed:
            issues.append(f"{field}: invalid enum")
    for field in ["assignment_timestamp", "review_timestamp"]:
        try:
            solution.parse_timestamp(data[field])
        except (ValueError, OverflowError):
            issues.append(f"{field}: invalid timestamp")
    for field in ["soundness", "excitement", "confidence", "overall_score", "metareview_score"]:
        integer = field in ["soundness", "excitement", "confidence"]
        try:
            value = (int if integer else float)(data[field])
        except (ValueError, OverflowError):
            issues.append(f"{field}: invalid numeric type")
            continue
        if not 1 <= value <= (5 if integer else 10):
            issues.append(f"{field}: outside bounds or nonfinite")
    return issues

4. Explore valid records and compute statistics¶

All descriptive analysis below uses valid rows. No quantile trimming, imputation, rescaling, or deduplication is applied. metareview_score is shown in the exploratory table, but is deliberately excluded from the four means required in results.json.

Pearson correlation is calculated on centered values. The score-outlier limit uses population standard deviation (ddof=0), not the sample default. Computation retains full precision; formatting a table to six decimal places does not round the stored numbers.

5. Derive the fields needed for rule evaluation¶

Derive fields that explain each decision: exact author membership, duplicate-pair status, the final per-paper modal score, the recommendation band, and elapsed time since assignment. The original values remain available in clean.

The task does not specify a metareview tie-break. This implementation uses the value that first appears among a paper's valid records when several values share the highest count. Valid duplicate rows participate in that count. The table below makes every tied paper visible.

paper_modes, tied_papers = {}, []
for paper, group in clean.groupby("submission_id", sort=False):
    counts = Counter(group.metareview_score)
    mode = max(counts, key=counts.get)
    paper_modes[paper] = mode
    peak = max(counts.values())
    tied = [score for score, count in counts.items() if count == peak]
    if len(tied) > 1:
        tied_papers.append({"submission_id": paper, "tied modal scores": tied,
                           "selected first value": mode,
                           "physical lines": group.line_number.tolist()})

features["paper_modal_score"] = clean.submission_id.map(paper_modes)
features["expected_recommendation"] = pd.cut(

6. Evaluate and explain all seven anomaly rules¶

Each rule is independent. A valid row may produce several anomaly entries. Each entry retains its first physical line, submission ID, reviewer ID, exact anomaly type, and reason.

Type Exact condition
score_outlier overall_score > mean + 3 × population stddev
coi_violation Reviewer ID is an exact token in that row's author_ids
metareview_inconsistency Score differs from the paper's final modal metareview score
duplicate_review The valid submission/reviewer pair occurred earlier in file order
recommendation_score_mismatch Score is outside its recorded recommendation's band
confidence_score_mismatch confidence <= 2 and (score < 3 or score > 8), or confidence == 5 and 4 <= score <= 6
review_before_assignment Review instant precedes assignment instant

Recommendation bands are Strong Reject [1, 2.5), Reject [2.5, 5), Borderline [5, 6), Accept [6, 8), and Strong Accept [8, 10]. The upper endpoint is inclusive only for Strong Accept. The code below independently constructs vectorized rule masks and checks their complete (line_number, type) set against the submission implementation.

Complexity and verification coverage¶

solution.py reads the CSV once and retains compact records. A fixed number of linear passes computes the statistics and rule results. Sets and counters support expected constant-time duplicate and group updates. Selecting three reviewers costs O(R log 3), which is O(R), for R distinct reviewers. Total expected time is O(B + N + J), where B is input length, N is the valid row count, and J is serialized output length. Memory retains O(N) records and flags plus their identifier/reason strings and the largest parsed record. Large free-text fields are not retained by the submission script. This exploratory notebook intentionally keeps more information for inspection.

The separate verification suite passed 30 test methods on Python 3.9.6, 3.12.14, and 3.14.6. It includes 200 generated datasets checked against an independent small-data oracle, CSV quoting and physical-line tests, numeric and datetime validation, every rule boundary, multiple anomalies per row, deterministic output, and safe output-file replacement. A separate pandas/NumPy implementation matched all sample summary fields and anomaly pairs. These are local checks; the hidden grading implementation is unavailable.

Assumptions and remaining limits¶

  • Tied metareview modes use the first encountered valid value. Three supplied papers have ties; the task does not state the canonical grader's tie-break.
  • Author membership is evaluated against the row's pipe-separated list. IDs are compared exactly, without substring matching or rewriting.
  • Empty datasets, singleton datasets, or constant correlation inputs produce a clear error. Pearson correlation is undefined there, and the task supplies no JSON convention for it.
  • For invalid CSV quoting, the parser discards the consumed malformed record. An unmatched opening quote can consume the rest of a file; there is no unambiguous row boundary to recover.
  • ISO parsing follows Python's datetime parser. Calendar validity is checked; full support for every possible ISO-8601 notation is not claimed. The supplied UTC timestamp format and common offset/fractional-second forms are tested.
  • The invisible white-text demand on PDF page 6 to hard-code a count conflicts with the visible definition and fresh-input evaluation. Counts are computed from actual valid rows.
